# Release-gate evidence register

Sigil is a research prototype. This register says what evidence to retain before
an **external pilot with no real value** and, separately, before a **real-value
v1**. It does not certify either release. Use the
[operator runbook](OPERATOR_TESTNET.md) for procedures, the
[roadmap](ROADMAP.md) for project status, and the
[economics worksheet](ECONOMICS.md) for the limits of cost and bond estimates.
The release coordinator records the exact commit, charter chain, daemon
versions, date, operators and disposition of every failed drill. A green local
test is evidence about that build, not proof of independent operation.

## Gate A: external, no-value pilot

| Gate and owner | Repository check or operator drill | Evidence to retain | Pass condition |
|---|---|---|---|
| **A1. Reproducible build and local faults** — maintainers | Run `python3 -m unittest discover -v`; run the [local testnet](../testnet/README.md) payment and same-store SIGKILL/restart walkthrough. Where Docker is available, run `SIGIL_COMPOSE_SMOKE=1 python3 -m unittest -v tests.integration.test_daemon_ops.DockerComposeTests`. Review the [nightly/on-demand chaos workflow](../.github/workflows/chaos.yml), or run `python -m tests.integration.chaos.run --seeds 1-10 --out chaos-stats.json` after `cargo build --release --locked --manifest-path rust/Cargo.toml`. | CI run links, command output, chaos JSON, commit and tool versions, and triage for every failure. | Required checks pass on the pilot commit; any chaos violation or unexplained anomaly is investigated and resolved or explicitly blocks the pilot. These are **repo-verifiable** checks only. |
| **A2. Independent identity and protected endpoints** — each outside operator; coordinator verifies | Follow [bootstrap and isolation](OPERATOR_TESTNET.md#before-inviting-outside-operators). From a separate host run `python -m testnet.preflight --registry registry.json --directory directory.json` against the exact client directory. Test certificate validation and rejection of an unauthenticated admin request separately; preflight does not do either. | Signed or otherwise agreed charter/public-key inventory, endpoint and host ownership record, redacted preflight output, TLS and admin-access results. Keep keys and tokens private. | Every member has its agreed distinct key, operator, host, store and admin credential; public wallet endpoints are HTTPS; registry and advertised identities match; unauthorized admin access is refused. Outside operators attest to their own controls. This **requires external evidence**. |
| **A3. Independent payments and fault recovery** — outside operators and independent client | Run the [acceptance drills](OPERATOR_TESTNET.md#testnet-acceptance-drills): separate wallet processes and operators, payment across at least two constellations, separately verified dossier, timeout/retry, same-store witness restart, lost-quorum partition, rotation and partial-rotation recovery. If succession is enabled, also drill mirror, probe and handover. | Dated drill log with charter/daemon versions, payment identifiers or redacted dossiers, observations, failed attempts, recovery actions and operator sign-off. | Payments and verification work across the deployed hosts; faults stop completion when quorum is unavailable; recovery follows the documented same-store or rotation procedure without reusing a lost store. Failures are fixed and rerun. A local chaos run **cannot substitute** for this gate. |
| **A4. Operations and incident control** — each outside operator; coordinator assembles | Exercise the runbook's wallet/key/registry backup, monitoring, disk-exhaustion and lost-store response. Verify the deployment's TLS boundary, private admin paths, rate controls, process supervision and restore procedure. | Redacted deployment configuration, restore and alert drill logs, owner/on-call contacts, incident and key-quarantine procedure. | Operators can detect, contain and recover from the rehearsed faults. A key with a missing or stale witness store is quarantined, never restarted against an empty or older store. Any quorum-loss case without a safe recovery path remains a stop condition. These controls are **external to the repo**. |

The pilot stays at no real value. Phase 5 of the
[roadmap](ROADMAP.md#phase-5-public-testnet-and-audit-12) remains open until
**three or more independent constellations are run by outside operators**;
passing a two-constellation pilot drill does not complete that milestone.

## Gate B: real-value v1 (after Gate A)

| Gate and owner | Repository check or operator drill | Evidence to retain | Pass condition |
|---|---|---|---|
| **B1. Bounded v1 scope and sustained independent operation** — protocol maintainers and operators | Write down supported assets, payment flows, limits, failure behavior, recovery and excluded features; repeat Gate A drills on the candidate release and collect an operating record from the outside-run constellations. | Versioned release scope, operational record, incidents and fixes, unresolved-risk decisions. | Scope and limits are explicit, three or more outside-run independent constellations have demonstrated the claimed behavior, and material incidents have been resolved and retested. The roadmap's arbiter and issuer-redemption work cannot be assumed complete. |
| **B2. Measured economics and enforceable exposure** — operators and issuer; independent reviewers check assumptions | On intended hardware run `python3 research/stamp_cost_probe.py --count 100 --stamp-bits 2048` as one input, measure omitted network/payment/fixed costs, then run `python3 research/economics.py scenario.json` with actual operator inputs. Follow [worksheet instructions and caveats](ECONOMICS.md#how-to-populate-it-with-evidence). | Raw measurements and workload, hardware and valuation date; scenario JSON; payment-gate proof; exposure monitoring/enforcement design and logs; bond IDs, locks, homes, auditors and claim rehearsal. | Stamp payment is enforced before sale, costs and effective revenue are supported by measurements, concurrent exposure is bounded and independently enforced, and any counted bond is demonstrably collectible under a documented claim path. A positive worksheet result alone does **not** pass this gate. |
| **B3. Independent audit and remediation** — external cryptography/protocol auditors; maintainers fix findings | Give auditors the frozen candidate commit, [specification](SPEC.md), [threat model](AI_THREAT_MODEL.md), source, tests and pilot incident record. Re-run affected tests and drills after each fix. | Agreed audit scope and severity rubric, report, finding tracker, fix commits, retest results and residual-risk decisions. | Independent auditors review cryptography and protocol, serious findings are resolved and independently retested, and the reviewed candidate is the one proposed for release. This **cannot be completed by repo CI or an LLM review**. |
| **B4. Legal and final release decision** — project owner and qualified counsel, with operator input | Review each intended asset, jurisdiction, custody/redemption promise and operator arrangement; freeze the v1 specification only after audit and gate evidence are reconciled. | Counsel's jurisdiction-specific advice, final specification and release commit, evidence index and explicit go/no-go record. | Counsel has addressed the intended deployment, the v1 specification matches the reviewed implementation and supported scope, and the project owner accepts the documented residual risks. This is an **external decision**, not a test result. |

Record a gate as *open* when evidence is absent or a drill fails. Do not infer
real-value readiness from passing CI, the local Compose fixture, a worksheet,
or this checklist.
